## Problem Statement

agsearch already searches local Claude Code and Codex CLI sessions and resumes them. Native agent search is weak; the old workaround was asking the live agent to find a past session. Six overlapping draft PRs (#9–#14) all claim pre-launch must-haves. The real product gap is **hit quality**: the top row should be the session you meant. Merging the whole pile would not measure that, and several drafts conflict or break documented behavior.

## What Makes This Cool

Type a messy phrase you would have asked the agent to hunt. The right session is row one. That is the post-worthy moment vs Claude/Codex built-in search. Resume working is assumed table stakes, not the demo.

## Constraints

- Fully local. No upload. README already promises no network and a small subprocess list (`fzf`, `pbcopy`, `claude`/`codex`).
- Single-file Python CLI plus `tests/`. Recent merges emptied ranking/snippet tests; #13 puts a synthetic pack back.
- Crowded 2026 category (ses, cass, recall, sessionwiki, …). More sources / embeddings / dashboards are not the wedge.
- `main` currently has uncommitted `agsearch` and `.gitignore` diffs vs `origin/main`. Resolve those before stacking PR merges.
- Open PRs are drafts from Cursor agents and overlap on resume + term-normalization.

## Premises

1. Double down on top-1 ranking, not a quality-report dashboard.
2. Include a change only if it is small and moves hit quality, or is documented follow-up hygiene (not this cut).
3. Sequence is **gold first**, then #13, then trimmed #9, then rescore the **same** gold list. Do not merge all six drafts. Do not call this “A then B.”
4. Status quo to beat: each product’s own search, and asking the agent to find the session.
5. Distribution already exists (`install.sh`). No new channel for this cut.

This design takes a **handwritten gold list + scorer** as the yardstick, plus a **fresh-branch rewrite** of preview (not a cherry-pick of #9). Enter-to-label JSONL, JSON/MCP, and two-doc BM25 stay later.

Eng-review outside voice (Claude subagent; Codex usage-capped): freeze the session corpus; do not label gold via `-n`; stash `_launch_dir` instead of discarding dirty `main`; rewrite preview in place. All of those were accepted.

## Approaches Considered

### Approach A: Merge tests + preview alignment only

Merge #13 (synthetic ranking tests). Extract preview-term helpers from #9. Close the rest. Fast GitHub motion; does not by itself move recall@1.

### Approach B: Gold-list yardstick only

Write 10–30 real query→expected-sid pairs; score recall@1 on current `main` before merging ranking diffs. Cleanest science; public `tests/` stays empty longer.

### Ruled out

- **Merge all six drafts then try A and B** — overlapping helpers, known resume bugs (#10/#12 launch dir and unquoted `cd`), #14 empty without #11, #11 latency is time-in-fzf, eval contamination.
- **Agent librarian JSON/MCP this cut** — cool, but agents will look bad if top-1 is still unmeasured.
- **Keep #11 telemetry + #14 quality-report** — not quick-and-true; dashboard with no events.
- **Enter click-log as the launch metric** — selected sid is click@1, circular with the click. Use expected sids as truth.

## Recommended Approach

**Gold first, then regression lock, then preview alignment, then rescore** (chosen). Approach B’s gold list is the baseline; Approach A’s merges happen after that list exists.

0. **Park resume work:** `git stash push -m launch-dir -- agsearch` (keep `.gitignore` `.guildly/` if you want). Do not discard. Commit `_launch_dir` later per `TODOS.md`.
1. **Snapshot:** Copy `~/.cache/agsearch/sessions.tsv` to `~/.cache/agsearch/gold-sessions.tsv` once. Scorer must load the copy, not live cache. IDF/recency/usage otherwise move @1 with no code change.
2. **Gold list:** ≥10 real queries. Label `expected_sid` from a `tests/` helper that `importlib`-loads `agsearch` and calls `rank_sessions` on the snapshot (print top-5). Do **not** label from `agsearch -n`. Paths: `~/.cache/agsearch/gold.jsonl` (gitignored if copied into the repo). Schema: `{query, expected_sid, observed_rank}`.
3. **Regression lock:** Merge #13 as-is. Does **not** change `rank_sessions`. Unittest green. Do not claim #13 moves @1. Synthetic pack uses its own `now`/`usage`; personal gold uses snapshot + real usage/`now` captured at snapshot time if we persist them — minimum is freeze the TSV rows.
4. **Preview alignment:** New branch from `main` after #13. Rewrite `render_preview` to `parse_query` + `keys = [stem if len(stem) >= 3 else term for term, stem in qterms]` and AND-match those keys on **message text** only. Highlight with those keys. Do **not** cherry-pick #9. Leave `rank_matches` / `print_matches` on raw `query.split()`. Close #9 as superseded.
5. **Rescore:** Same gold + same snapshot. recall@1 = expected_sid == `rank_sessions(...)[0]`. **Preview PR must leave @1 unchanged** (delta 0). Further **ranking** PRs require an @1 delta on this snapshot.
6. **PR hygiene:** Close #14, #11, #10, #12 without merging. Follow-ups live in `TODOS.md`.

Enter labeling (`--label` → `~/.cache/agsearch/labels.jsonl`) is **not** this cut. Optional later: after fzf returns the selected row, re-run `parse_query` + `rank_sessions` to derive rank/top-5 (fzf does not emit them). Default off.

Optional later (not this cut): two-field BM25; `agsearch -n --json` for agents.

## Failure modes

- Scorer reads live `sessions.tsv` → @1 moves without code change. Mitigation: missing snapshot must error.
- Gold labeled from `-n` → metric ≠ TUI. Mitigation: helper-only protocol.
- Discard dirty `agsearch` → lose `_launch_dir`. Mitigation: stash first.
- Cherry-pick #9 → forbidden sort lands. Mitigation: rewrite three lines.
- Preview `json.load(INDEX_PATH)` fails → already prints `(session not found)`.

## Diagrams

```
query ─┬─ TUI _filter ─ parse_query ─ rank_sessions(sessions.tsv) ─ fzf row
       ├─ _preview ─ parse_query ─ keys AND on message text ─ match count
       ├─ -n ─ rank_matches(raw split) ─ NOT used for gold
       └─ gold helper ─ rank_sessions(gold-sessions.tsv) ─ expected_sid
```

CODE PATHS                                            USER FLOWS
[+] rank_sessions                                     [+] TUI search → top row
  ├── [GAP] gold helper on snapshot                   ├── [GAP] [→EVAL] 10 personal queries
  └── [★★  TESTED] after #13 synthetic pack           └── [GAP] preview stem count
[+] render_preview
  ├── [GAP] stem keys on body
  └── [GAP] index missing
[+] rank_matches / -n
  └── [GAP] CRITICAL: still exact AND after preview

Sequential implementation, no parallelization opportunity (single `agsearch` file).
